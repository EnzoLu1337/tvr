# Three.js Lab 3

Простой учебный проект на `Three.js` для лабораторной работы по взаимодействию в 3D-сцене.

Проект специально сделан без лишних библиотек и без сложной архитектуры:
- есть один класс `Engine`
- сцена создается вручную
- камера вращается вручную
- выбор объектов делается через `THREE.Raycaster`
- информация выводится в один блок `#info`

Идея проекта: сделать код таким, чтобы его можно было читать сверху вниз и понимать, что происходит.

## Что умеет программа

- показывает 3D-сцену с 4 объектами:
  - куб
  - сфера
  - конус
  - цилиндр
- позволяет вращать камеру мышью
- позволяет приближать и отдалять камеру колесом мыши
- подсвечивает объект при наведении
- выбирает объект по клику
- показывает имя и тип выбранного объекта
- анимирует выбранный объект изменением масштаба

## Общая логика работы

После запуска создается объект:

```js
new Engine();
```

Это означает:
- создается экземпляр класса
- внутри конструктора создаются сцена, камера, рендерер и служебные поля
- дальше строится сцена
- затем подключаются события мыши
- затем запускается бесконечная анимация

То есть `Engine` здесь играет роль простого "движка" приложения.

## Почему используется класс `Engine`

Класс нужен, чтобы все данные сцены лежали в одном месте:
- `this.scene`
- `this.camera`
- `this.renderer`
- `this.raycaster`
- `this.objects`
- `this.selectedObject`

Если бы всё было написано набором отдельных глобальных переменных и функций, было бы сложнее понимать, какие данные к чему относятся.

Здесь класс используется по учебному и очень просто:
- хранит состояние
- содержит методы
- управляет жизненным циклом сцены

Без наследования, без нескольких классов, без сложной ООП-иерархии.

## Разбор класса `Engine`

### 1. `constructor()`

Конструктор вызывается при создании объекта `new Engine()`.

Он делает основную начальную настройку:

1. Находит HTML-элемент `#info`
2. Создает сцену `THREE.Scene`
3. Создает камеру `THREE.PerspectiveCamera`
4. Создает рендерер `THREE.WebGLRenderer`
5. Создает `Clock`, `Raycaster`, массив объектов
6. Создает параметры камеры
7. Создает служебные переменные для мыши
8. Вызывает:
   - `createScene()`
   - `updateCamera()`
   - `updateInfo()`
   - `bindEvents()`
   - `animate()`

Именно конструктор запускает весь проект.

## Поля класса

### Основные поля

- `this.scene` — 3D-сцена
- `this.camera` — камера
- `this.renderer` — рендерер WebGL
- `this.clock` — таймер для плавной анимации
- `this.raycaster` — луч для поиска объекта под курсором
- `this.mouse` — координаты мыши в нормализованном виде
- `this.objects` — массив объектов, по которым можно выполнять поиск лучом

### Поля камеры

- `this.target` — точка, вокруг которой вращается камера
- `this.radius` — расстояние камеры до центра
- `this.azimuth` — горизонтальный угол
- `this.polar` — вертикальный угол

### Поля мыши

- `this.isDragging` — идет ли сейчас перетаскивание
- `this.hasMoved` — была ли мышь сдвинута, чтобы отличать клик от перетаскивания
- `this.startX`, `this.startY` — где началось движение
- `this.lastX`, `this.lastY` — предыдущая точка мыши

### Поля выбора

- `this.hoveredObject` — объект под курсором
- `this.selectedObject` — выбранный объект
- `this.animationTime` — время для анимации выбранного объекта

## Создание сцены

### Метод `createScene()`

Этот метод добавляет в сцену:
- пол
- ambient light
- directional light
- point light
- 4 геометрических объекта

### Почему именно такой набор света

#### `AmbientLight`

Дает общий мягкий свет, чтобы объекты не были слишком темными.

#### `DirectionalLight`

Похож на солнечный свет. Нужен, чтобы форма объектов читалась лучше и были тени.

#### `PointLight`

Точечный источник света. Добавляет объемности и делает сцену живее.

### Почему есть пол

Пол нужен, чтобы:
- сцена не висела в пустоте
- было ощущение пространства
- тени выглядели естественно

## Создание объектов

### Метод `addObject(...)`

Этот метод создает один объект сцены и добавляет его в массив `this.objects`.

Аргументы:
- `name` — имя объекта для вывода в `#info`
- `type` — тип объекта
- `geometry` — геометрия `Three.js`
- `color` — цвет объекта
- `x, y, z` — позиция объекта

### Что кладется в `userData`

У каждого объекта есть:

```js
mesh.userData = {
  name,
  type,
  baseColor: new THREE.Color(color),
  baseScale: 1,
};
```

Это удобно, потому что в `userData` можно хранить свои данные.

Здесь это нужно для:
- вывода имени
- вывода типа
- восстановления исходного цвета
- восстановления исходного масштаба

## Как работает камера

### Идея

Камера не двигается "как игрок", а вращается вокруг одной точки:

```js
this.target = new THREE.Vector3(0, 1, 0);
```

Это значит, что камера всегда смотрит на центр сцены.

### Параметры камеры

- `radius` — насколько камера далеко от центра
- `azimuth` — поворот по горизонтали
- `polar` — поворот по вертикали

### Метод `updateCamera()`

Этот метод переводит сферические координаты в обычные 3D-координаты:

```js
x = target.x + radius * sin(polar) * sin(azimuth)
y = target.y + radius * cos(polar)
z = target.z + radius * sin(polar) * cos(azimuth)
```

После этого камера направляется в центр сцены:

```js
this.camera.lookAt(this.target);
```

### Зачем это нужно

Такой способ очень удобен для лабораторной, потому что:
- камера всегда остается вокруг сцены
- не улетает случайно в сторону
- легко вращается мышью
- легко приближается и отдаляется колесом

## Как работает мышь

### Метод `bindEvents()`

Подписывает программу на события:
- `mousedown`
- `mousemove`
- `mouseup`
- `mouseleave`
- `wheel`
- `resize`

### Почему используются обычные mouse-события

Потому что так проще читать код.

Для учебной лабораторной этого достаточно:
- логика понятная
- меньше технических деталей
- легче объяснить на защите

## Как отличить клик от вращения

Когда нажата кнопка мыши:
- запоминается стартовая позиция
- если мышь почти не сдвинулась, это клик
- если мышь заметно сдвинулась, это вращение камеры

Порог проверяется здесь:

```js
Math.hypot(event.clientX - this.startX, event.clientY - this.startY) > 4
```

Если расстояние больше `4`, значит это уже не клик, а движение.

## Как работает вращение камеры

Во время `mousemove`, если зажата мышь:
- вычисляется `dx`
- вычисляется `dy`
- по ним меняются углы камеры:

```js
this.azimuth -= dx * 0.008;
this.polar += dy * 0.008;
```

Потом вертикальный угол ограничивается:

```js
this.polar = THREE.MathUtils.clamp(this.polar, 0.45, 1.45);
```

Это нужно, чтобы камера не переворачивалась вверх ногами.

## Как работает приближение и отдаление

В `onWheel(event)`:
- читается `deltaY`
- меняется `radius`
- значение ограничивается
- камера пересчитывается

```js
this.radius += event.deltaY * 0.01;
this.radius = THREE.MathUtils.clamp(this.radius, 4, 14);
```

Это не дает камере:
- слишком сильно приблизиться
- слишком далеко улететь

## Как работает `Raycaster`

### Идея

`Raycaster` создает луч из камеры в сторону курсора.

Этот луч проверяет, пересекает ли он какие-то объекты сцены.

### Шаг 1. Перевод мыши в нормализованные координаты

Метод `updateMouse(event)` переводит координаты мыши в диапазон:
- по X: от `-1` до `1`
- по Y: от `-1` до `1`

Это формат, который нужен `Three.js`.

### Шаг 2. Создание луча

В `getIntersectedObject()`:

```js
this.raycaster.setFromCamera(this.mouse, this.camera);
```

Здесь луч строится от камеры через точку курсора.

### Шаг 3. Поиск пересечений

```js
const intersects = this.raycaster.intersectObjects(this.objects);
```

Если массив не пустой, значит луч попал в объект.

### Что возвращается

Если пересечение найдено:
- берется первый объект
- он считается ближайшим к камере

```js
return intersects.length > 0 ? intersects[0].object : null;
```

## Как работает подсветка

### `hoveredObject`

В этом поле хранится объект, на который сейчас наведен курсор.

### `selectedObject`

В этом поле хранится выбранный объект.

### Метод `updateObjectStyles()`

Он проходит по всем объектам и:
1. Возвращает им базовый цвет
2. Убирает старую подсветку
3. Добавляет слабую подсветку объекту под курсором
4. Добавляет более сильную подсветку выбранному объекту

Подсветка делается через `emissive`.

Это удобно, потому что:
- объект не становится совсем другим
- визуально видно выделение
- код остается простым

## Как работает выбор объекта

В `onMouseUp(event)`:
- если мышь была нажата и почти не двигалась, это считается кликом
- тогда вызывается:

```js
this.setSelectedObject(this.getIntersectedObject());
```

Если клик был по пустому месту, `getIntersectedObject()` вернет `null`.

Тогда выбор просто сбросится.

## Как выводится информация

### Метод `updateInfo()`

Если объект не выбран:

```js
Выбранный объект: нет
```

Если объект выбран:

```js
Имя: ...
Тип: ...
```

Это самый простой вариант, который прямо соответствует заданию.

## Как работает анимация

### Метод `update()`

Каждый кадр:
- берется `dt` из `clock`
- увеличивается `animationTime`

Если объект выбран, его масштаб плавно меняется:

```js
const scale = 1 + 0.12 * Math.sin(this.animationTime * 5);
object.scale.set(scale, scale, scale);
```

Если объект не выбран:

```js
object.scale.set(1, 1, 1);
```

### Почему выбрана именно такая анимация

Потому что она:
- простая
- заметная
- не ломает позицию объекта
- легко объясняется

## Как работает рендер-цикл

### Метод `animate()`

Это бесконечный цикл отрисовки:

```js
requestAnimationFrame(() => this.animate());
this.update();
this.renderer.render(this.scene, this.camera);
```

Каждый кадр:
1. вызывается `update()`
2. пересчитывается анимация
3. сцена отрисовывается

## Полный порядок работы программы

Вот цепочка целиком:

1. Создается `new Engine()`
2. Конструктор создает основные объекты `Three.js`
3. `createScene()` добавляет пол, свет и 4 фигуры
4. `updateCamera()` выставляет стартовую позицию камеры
5. `bindEvents()` подключает мышь и resize
6. `animate()` запускает цикл отрисовки
7. Пользователь двигает мышь:
   - меняется `hoveredObject`
   - объект подсвечивается
8. Пользователь кликает:
   - через `Raycaster` находится объект
   - он записывается в `selectedObject`
   - `#info` обновляется
   - объект начинает пульсировать
9. Пользователь тащит мышь:
   - меняются углы камеры
   - камера вращается вокруг сцены
10. Пользователь крутит колесо:
   - меняется расстояние камеры

## Что можно быстро менять в коде

### Изменить стартовую камеру

В конструкторе:

```js
this.radius = 8;
this.azimuth = Math.PI / 4;
this.polar = 1.05;
```

### Изменить скорость вращения камеры

В `onMouseMove()`:

```js
this.azimuth -= dx * 0.008;
this.polar += dy * 0.008;
```

### Изменить силу анимации

В `update()`:

```js
const scale = 1 + 0.12 * Math.sin(this.animationTime * 5);
```

Здесь:
- `0.12` — насколько сильно меняется размер
- `5` — насколько быстро идет пульсация

### Изменить текст в блоке информации

В `updateInfo()`.

### Изменить подсветку

В `updateObjectStyles()`.

## Почему этот вариант можно считать удачным для учебной лабы

- Весь код в одном месте
- Есть ООП, но без лишней сложности
- Нет внешних контролов камеры
- Нет сложной архитектуры
- Все требования лабораторной выполнены
- Код можно разбирать по методам
- На защите можно легко объяснить, что делает каждый блок

## Что здесь специально не использовано

Чтобы код было проще понимать, здесь специально не используются:

- `OrbitControls`
- отдельные классы для камеры, сцены и объектов
- менеджеры состояний
- сложные UI-компоненты
- сторонние библиотеки для интерфейса
- продвинутая система материалов

## Возможные вопросы на защите и короткие ответы

### Зачем нужен `Raycaster`?

Чтобы определить, в какой объект пользователь "попал" курсором.

### Почему координаты мыши переводятся в диапазон `-1..1`?

Потому что `Three.js` работает с нормализованными координатами экрана для построения луча.

### Почему камера вращается через углы, а не двигается напрямую?

Потому что так проще удерживать ее вокруг центра сцены.

### Зачем нужен массив `this.objects`?

Чтобы `Raycaster` проверял пересечения только с нужными объектами.

### Почему информация хранится в `userData`?

Потому что это удобное место для пользовательских свойств объекта.
